# ADR-004: 消除时倒计时奖励机制

## 状态

**Accepted** ✅ | 日期：2026-06-20 | 沐风 11:43 指示
**更新** | 日期：2026-06-21 | v1.0.3 实现确定

## 背景

沐风要求在游戏机制中补充：**当成功触发消除时，重置倒计时**。

这是对 v1.0 需求（FR-6.1 倒计时固定 60 秒）的修改。原 MTK 版本的魔法寿司没有这个机制，是**现代化增强**。

## 决策

**采用方案 A（v1.0.3 修订版）：每次成功消除 → 倒计时重置回 60s**

> 原方案 A（+5s，上限 90s）在 v1.0.3 沐风反馈后修订。消除 → 重置到 60s，奖励为"补满到 60 的差值"，不再累加。

```kotlin
object TimerEngine {
    const val INITIAL_SECONDS = 60
    const val REWARD_SECONDS = 5      // 保留常量，文档/兼容性用
    const val MAX_SECONDS = 90        // 保留常量，v1.0.3 不参与计算

    // v1.0.3: 消除 → reset to 60s
    fun rewardOnMatch(remainingSeconds: Int, matches: List<Match>): Pair<Int, Int> {
        if (matches.isEmpty()) return remainingSeconds to 0  // FR-6.9
        val newRemaining = INITIAL_SECONDS
        val actualReward = (newRemaining - remainingSeconds).coerceAtLeast(0)
        return newRemaining to actualReward
    }
}
```

**示例（v1.0.3）：**
- `rewardOnMatch(50, [match])` → `(60, 10)` — 从 50 补到 60
- `rewardOnMatch(88, [match])` → `(60, 0)` — 已超 60，重置后无增量
- `rewardOnMatch(60, [match])` → `(60, 0)` — 刚好 60，不变
- `rewardOnMatch(50, [])` → `(50, 0)` — 无匹配（无效交换），不触发 FR-6.9

## 备选方案对比

| 方案 | 描述 | 节奏 | 风险 |
|------|------|------|------|
| **A（修订）** ✅ | 消除 → 重置到 60s | 续命但不累加 | 低 |
| A（原始） | 消除 +5s，上限 90s | 鼓励连锁累加 | 中（高手越打越久） |
| B | 消除恢复到 60s（无增量） | 节奏停滞 | 中 |
| C | 仅 combo ≥ 2 +5s | 鼓励高 combo | 中（普通消除无反馈） |
| D | +1s 不设上限 | 温和 | 高（可刷分挂机） |

**选修订 A 的核心理由：**
- 玩家消除获得续命，但不会"越打越久"（60s 上限打破了这个担忧）
- 低于 60s 时消除补回时间，奖励明确；高于 60s 时消除也重置但奖励为 0，体验一致

## 后果

### 正面
- ✅ 玩家消除时获得双重反馈（分数 + 补满时间），强化成就感
- ✅ 低于 60s 时消除有实际奖励（+Xs），高于 60s 时消除重置到 60（无时间膨胀）
- ✅ 与拖动交换增强方向一致：都是让游戏"更有操作回报"

### 中性
- ℹ️ 不影响 1:1 复刻的核心玩法
- ℹ️ 奖励显示的 +Xs 飘字（实际补满量）需要在 UI 层正确渲染

## 实现要点

### TimerEngine 单例（v1.0.3）

```kotlin
object TimerEngine {
    const val INITIAL_SECONDS = 60
    const val REWARD_SECONDS = 5      // 仅文档/兼容性保留
    const val MAX_SECONDS = 90         // v1.0.3 不参与计算

    fun rewardOnMatch(remainingSeconds: Int, matches: List<Match>): Pair<Int, Int> {
        if (matches.isEmpty()) return remainingSeconds to 0  // FR-6.9
        val newRemaining = INITIAL_SECONDS
        val actualReward = (newRemaining - remainingSeconds).coerceAtLeast(0)
        return newRemaining to actualReward
    }

    fun isGameOver(remainingSeconds: Int): Boolean = remainingSeconds <= 0
}
```

### GameViewModel 调用点

```kotlin
// After a successful cascade round
val (newRemaining, reward) = TimerEngine.rewardOnMatch(remainingSeconds, matches)
if (reward > 0) showRewardFloatingText("+${reward}s")
remainingSeconds = newRemaining
```
