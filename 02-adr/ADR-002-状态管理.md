# ADR-002: 状态管理方案

## 状态

**Accepted** ✅ | 日期：2026-06-20

## 背景

Magic Sushi 需要管理的状态包括：
1. **棋盘状态**（7×7 寿司网格）
2. **游戏阶段**（IDLE / ANIMATING / GAME_OVER）
3. **分数**（当前分 + 最高分）
4. **倒计时**（剩余秒数）
5. **选中寿司**（当前选中的寿司坐标）
6. **连锁计数**（combo 次数）

需要选择合适的状态管理方案，平衡响应式和可测试性。

## 决策

**采用：`ViewModel` + `StateFlow` + `MutableStateFlow`**

```kotlin
// GameState（不可变数据类）
data class GameState(
    val board: Board,
    val score: Int,
    val highScore: Int,
    val remainingSeconds: Int,
    val selectedTile: GridPos?,
    val phase: GamePhase,
    val comboCount: Int,
    val isMuted: Boolean,
    val lastMatch: List<Match>? = null
)

// GameViewModel
class GameViewModel(
    private val prefsRepo: PrefsRepository
) : ViewModel() {

    private val _state = MutableStateFlow(GameState.initial())
    val state: StateFlow<GameState> = _state.asStateFlow()

    // 核心逻辑委托给各 Engine
    private val boardEngine = BoardEngine()
    private val matchEngine = MatchEngine()
    private val cascadeEngine = CascadeEngine()
    private val scoreEngine = ScoreEngine()
    private val gravityEngine = GravityEngine()

    // UI 事件入口
    fun onTileTapped(pos: GridPos) { ... }
    fun onDragEnd(from: GridPos, direction: Direction) { ... }
    fun onToggleMute() { ... }
    fun onRestart() { ... }
}
```

## 备选方案对比

| 维度 | 方案 A：ViewModel+StateFlow（选中） | 方案 B：Compose State（remember+mutableStateOf） | 方案 C：Redux（ViewModel + Reducer） |
|------|-----------------------------------|-----------------------------------------|----------------------------------|
| 可测试性 | ✅ ViewModel 可单元测试 | ⚠️ 需人工合成状态 | ✅ Reducer 纯函数极易测试 |
| 状态不可变性 | ✅ StateFlow 推送不可变快照 | ⚠️ 需手动约束 | ✅ Action → State 是纯函数 |
| 与生命周期协同 | ✅ ViewModel 生命周期感知 | ⚠️ 需 `rememberSaveable` | ✅ 同 ViewModel |
| 多人协作友好 | ✅ 单向数据流清晰 | ⚠️ 多处 `state.value =` 易乱 | ✅ Action 模式强制约束 |
| 适合复杂状态 | ✅（中等复杂度足够） | ⚠️（超过 10 个状态字段开始乱） | ✅（适合超复杂状态机） |
| Compose 集成 | ✅ `collectAsState()` | ✅ 直接用 | ⚠️ 需 Adapter |

**最终选方案 A** 的核心理由：
- Magic Sushi 状态中等复杂（7×7 棋盘 + 连锁 + 倒计时），ViewModel+StateFlow 足够
- ViewModel 有生命周期感知（屏幕旋转不丢状态）
- StateFlow 对 Compose 的 `collectAsState()` 有原生支持
- 各 Engine 纯逻辑，可独立单元测试

## 后果

### 正面
- ✅ ViewModel 提供结构化的状态容器，`GameState` 是单一真相源
- ✅ `StateFlow` 推送式更新，Compose 自动重绘，无需手动 `invalidate()`
- ✅ 多人协作时单向数据流易于理解

### 负面
- ⚠️ `GameState` 包含棋盘 7×7 = 49 个寿司对象，复制成本需注意（但 Kotlin data class + copy() 足够轻量）
- ⚠️ `phase: ANIMATING` 期间状态更新频繁，需确保动画帧不被打断

### 中性
- ℹ️ 如果未来状态复杂度暴涨（加道具/关卡），可平滑迁移到 Redux 模式

## 核心状态转换

```kotlin
sealed class GamePhase {
    object IDLE : GamePhase()        // 等待玩家操作
    object ANIMATING : GamePhase()  // 动画播放中，禁止输入
    data class GAME_OVER(val finalScore: Int) : GamePhase()
}

fun GameViewModel.stateTransition(newPhase: GamePhase) {
    _state.update { it.copy(phase = newPhase) }
}
```
