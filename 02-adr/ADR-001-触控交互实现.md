# ADR-001: 触控交互实现方式

## 状态

**Accepted** ✅ | 日期：2026-06-20

## 背景

Magic Sushi 是触屏游戏，需要支持：
1. **点击两次交换**（MTK 原版交互）
2. **拖动交换**（沐风要求的增强功能）

Android Compose 提供了多种触控处理方案，需要选一个最适合棋盘类游戏的。

## 决策

**采用：`PointerInputScope` + `detectDragGestures` + `detectTapGestures`（Compose 原生手势 API）**

```kotlin
@Composable
fun SushiTile(
    sushi: SushiTile,
    onTap: () -> Unit,
    onDragStart: (Offset) -> Unit,
    onDragEnd: (Offset) -> Unit,
    onDrag: (Offset) -> Unit
) {
    var offset by remember { mutableStateOf(Offset.Zero) }

    Box(
        modifier = Modifier
            .pointerInput(sushi.id) {
                detectTapGestures(
                    onTap = { onTap() },
                    onLongPress = { onDragStart(firstDragOffset) }
                )
            }
            .pointerInput(sushi.id) {
                detectDragGestures(
                    onDragStart = { onDragStart(it) },
                    onDragEnd = { onDragEnd(offset) },
                    onDrag = { change, dragAmount ->
                        offset += dragAmount
                        onDrag(offset)
                    }
                )
            }
    ) {
        // 寿司绘制
    }
}
```

## 备选方案对比

| 维度 | 方案 A：PointerInputScope（选中） | 方案 B：Custom View + ViewGroup | 方案 C：GestureDetector |
|------|--------------------------------|-------------------------------|---------------------|
| Compose 集成 | ✅ 原生 | ❌ 需要 AndroidView | ⚠️ 可用但非 Compose 风格 |
| 拖动精度 | ✅ 可获取 `Offset` 实时位置 | ✅ 高 | ⚠️ 精度一般 |
| 多指支持 | ✅ 支持 | ✅ 支持 | ⚠️ 需额外配置 |
| 代码复杂度 | 中（需区分 tap/drag） | 高（需处理 Touch 事件分发） | 低 |
| 与 Canvas 协同 | ✅ CanvasComposable + Modifier | ⚠️ View.draw() 混合 | ⚠️ 需转 Canvas | 
| 与 ViewModel 协同 | ✅ StateFlow | ⚠️ 需要 observeAsState | ✅ StateFlow |
| 学习成本 | 中（Compose 手势 API） | 高（View 系统 + Touch 机制） | 低 |

**最终选方案 A** 的核心理由：
- Compose 生态内完全自洽，无需 AndroidView 桥接
- `detectDragGestures` 提供实时 Offset，可在拖动中渲染跟随手指的寿司（半透明 + 位移）
- 与 CanvasComposable 同一套声明式 UI 体系，状态驱动重绘

## 后果

### 正面
- 🎯 拖动寿司可以做到"跟随手指"的视觉效果（半透明 + 位移补偿）
- 🎯 tap/drag 可以在同一个 Composable 中通过 `pointerInput` 区分
- 🎯 与 Compose 动画系统无缝集成（`animateOffsetAsState`）

### 负面
- ⚠️ 需要自己实现"拖动阈值"判断（< 30% 寿司宽度 → 点击，否则交换）
- ⚠️ 长按和拖动的边界需要精确处理（避免长按触发 drag 时同时触发 tap）

### 中性
- ℹ️ iOS 移植时需要用 SwiftUI 的 DragGesture 重写（如果以后要做 iOS 端）

## 实现要点

1. **拖动阈值**：
   ```kotlin
   val dragThreshold = sushiSize * 0.3f
   if (offset.getDistance() < dragThreshold) {
       // 判定为点击
   }
   ```

2. **相邻判定**（拖动结束后）：
   ```kotlin
   fun getSwipeDirection(offset: Offset): Direction? {
       val threshold = sushiSize * 0.5f
       return when {
           offset.x > threshold -> Direction.RIGHT
           offset.x < -threshold -> Direction.LEFT
           offset.y > threshold -> Direction.DOWN
           offset.y < -threshold -> Direction.UP
           else -> null
       }
   }
   ```

3. **视觉反馈**：
   - 拖动中：被拖动寿司 `alpha = 0.7f`，跟随手指
   - 原位置：留下虚影（ghost）
   - 有效交换：两个寿司同时滑动动画
   - 无效交换（无三连）：弹回动画
