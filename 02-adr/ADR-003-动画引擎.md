# ADR-003: 动画引擎方案

## 状态

**Accepted** ✅ | 日期：2026-06-20

## 背景

Magic Sushi 需要以下动画：

| 动画场景 | 持续时间 | 复杂度 |
|---------|---------|-------|
| 寿司选中（高亮缩放） | 200ms | 低 |
| 交换滑动 | 250ms | 低 |
| 消除（缩小+消失） | 200ms | 低 |
| 下落填充 | 300ms | 中 |
| 连锁等待 | 150ms | 低 |
| Combo 提示文字弹出 | 400ms | 低 |
| 分数跳动 | 300ms | 低 |
| 结算弹窗弹出 | 300ms | 低 |

需要选一个动画引擎，要求：
- 与 Compose 深度集成
- 可中断/可取消（消除动画播放中被下落打断）
- 支持手势驱动（拖动跟随）

## 决策

**采用：Compose Animation API（`animate*AsState` + `AnimatedVisibility` + `updateTransition`）**

```kotlin
// 示例 1：消除动画
val scale by animateFloatAsState(
    targetValue = if (isEliminating) 0f else 1f,
    animationSpec = tween(durationMillis = 200, easing = EaseOut),
    label = "eliminate"
)

// 示例 2：下落动画
val offsetY by animateFloatAsState(
    targetValue = targetY,
    animationSpec = tween(durationMillis = 300, easing = EaseInOut),
    label = "fall"
)

// 示例 3：选中高亮
val scale by animateFloatAsState(
    targetValue = if (isSelected) 1.15f else 1f,
    animationSpec = spring(dampingRatio = Spring.DampingRatioMediumBouncy),
    label = "select"
)
```

**不采用 Lottie** 的原因：
- Lottie 是为了还原设计师复杂动画（如 AE 导出），我们的寿司消除动画很简单
- Lottie 引入额外依赖（lottie-compose），增加 APK 大小
- Lottie 的手势驱动支持不如 Compose 原生 API 直观

## 备选方案对比

| 维度 | 方案 A：Compose Animation（选中） | 方案 B：Lottie | 方案 C：Property Animation（ObjectAnimator） |
|------|------------------------------|--------------|----------------------------------------|
| Compose 集成 | ✅ 原生 | ⚠️ lottie-compose | ❌ AndroidView 桥接 |
| APK 大小 | ✅ 0（Compose 内置） | ⚠️ +1.5MB | ⚠️ +200KB |
| 动画控制精度 | ✅ 帧级控制 | ⚠️ 受限于 JSON | ✅ 精细控制 |
| 手势驱动 | ✅ `Offset` 实时驱动 | ❌ 不支持 | ⚠️ 需手动管理 |
| 适用场景 | 简单/中等动画 | 复杂设计师动画 | View 系统动画 |
| 连锁动画链 | ✅ `Animatable.snapTo` + `launchIn` | ⚠️ 可行但复杂 | ⚠️ 需要 AnimationSet |

**最终选方案 A** 的核心理由：
- 所有动画场景都是简单 Transform（scale/translate/alpha），无需 Lottie 的复杂度
- Compose Animation 与 CanvasComposable 无缝集成
- `animate*AsState` 自动处理中断/取消

## 后果

### 正面
- ✅ APK 大小零增量（Compose 内置）
- ✅ 手势驱动动画（如拖动跟随手指）天然支持
- ✅ 状态驱动：动画直接绑定 `GameState`，无需手动同步

### 负面
- ⚠️ 连锁动画（消除 → 下落 → 再次消除）需要手动编排时序
  ```kotlin
  // 需要这样编排：
  suspend fun playCascade() {
      // 1. 播放所有匹配的消除动画（并行）
      launchIn(消除动画，150ms)
      awaitAll()
      // 2. 下落动画
      下落动画，300ms
      // 3. 再次检测
      detectCascade()?.let { playCascade() }
  }
  ```

### 中性
- ℹ️ 如果未来想加更华丽的粒子特效，需要评估 Lottie 或自绘粒子系统

## 动画时序编排（关键）

```kotlin
// CascadeSequence - 编排整个消除→下落→连锁流程
class CascadeSequence(
    private val scope: CoroutineScope,
    private val onStateUpdate: (GameState) -> Unit
) {
    suspend fun play(board: Board, comboCount: Int): GameState {
        var current = board
        var combo = comboCount

        while (true) {
            val matches = MatchEngine.detectMatches(current)
            if (matches.isEmpty()) break

            // 1. 消除动画（200ms）
            matches.forEach { animateElimination(it.tiles) }
            delay(200)

            // 2. 下落填充（300ms）
            current = GravityEngine.applyGravity(current, matches)
            animateFall(current)
            delay(300)

            combo++
        }
        return current.copy(comboCount = combo)
    }
}
```
